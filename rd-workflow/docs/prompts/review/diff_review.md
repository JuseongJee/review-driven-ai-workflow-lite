최신 변경 diff를 리뷰해줘.

이의 문턱 (상세: `FILE_BASED_REVIEW_PIPELINE.md` 「이의 문턱」): 종결을 막는 이의는 (가) 실사용의 잘못된 결과·데이터 손실·보안·회귀 (나) 요청·AC·spec 이탈, 다음 단계를 잘못 이끄는 누락·모호함 (다) 검증이 결함을 덮지 못함(테스트 없음·거짓 통과)뿐이다. 이의마다 `경로:` 줄에 현실에서 일어나는 경로를 적는다. 그 밖(문구·서식·주석·유지보수성·복잡성, 증거·기록 형식, 실패 주입으로만 재현되는 경로, rd 가 만들지 않는 입력의 경계)은 Summary 끝 `메모:` 줄로 내며 종결을 막지 않는다.

검토 기준
- 논리 버그
- 회귀 위험
- 성능 문제
- 보안 문제
- 치명 결함 범주 — diff 밖 호출부·소비처까지 읽고 확인한다
  - 데이터 안전: 삭제·덮어쓰기·부분 실패 뒤 데이터가 손실되거나 어긋나는 경로가 있는가
  - 경쟁 조건: 동시 실행·재실행·중단 후 재개에서 상태가 깨지는가
  - 신뢰 경계: 외부 입력·LLM 출력·파일 내용이 검증 없이 명령·경로·쿼리(셸 인젝션 포함)로 들어가는가
  - 열거형 완전성: 새 값·상태를 모든 소비처가 처리하는가
- CURRENT_TASK.md 정합: 커밋된 `CURRENT_TASK.md`가 HEAD 기준 현재 단계(Status·Spec·Plan·Next Step)와 일치하는가
- 변이 증거: 새·변경 필수 대상 단언(부정 명제·회귀)의 결과표에 `생존`·원복 `미확인` 행이 있으면 이의. 결과표 누락·행 갱신 누락·기준 SHA·`무효`·`미검증` 사유 형식은 `메모:` 다. 직접 주입은 작업 트리 밖 사본에서만 한다 (`rd-workflow/docs/guides/mutation-check.md`)
- spec·plan·AC 이탈: diff 가 spec·plan(`full`) 또는 REQUEST AC(`standard`)와 어긋나는가. 경로는 `CURRENT_TASK.md` 의 `## Spec`·`## Plan` 에서 찾는다. 사유가 spec 의 「구현 중 변경」 절이나 REQUEST 에 없으면 이의
- 사용자 확인: 사용자에게 보이는 결과나 백그라운드 동작이 바뀌면 결과·진행·실패를 사용자가 볼 수 있는가. 빠졌거나 spec·AC 와 다르면 이의. 사용자에게 닿지 않는 내부 변경은 제외
- 범위 밖 변경: REQUEST·CURRENT_TASK 에 적힌 범위를 벗어난 리팩터링·포맷·파일이 있는가 (spec·AC 에 없는 변경)
- 테스트 거짓말: 새·변경 테스트의 동어반복·구조 결합·mock 과다(정의: `core.md` 테스트 규칙). 검증 결론이 바뀔 때만 이의
- macOS 기본 도구: 새·변경 셸 테스트는 그 파일만 `PATH=/usr/bin:/bin:/usr/sbin:/sbin bash <파일>` 로 한 번 실행한다(이 PATH 는 BSD `sed`·bash 3.2 다). 개발 머신의 GNU 도구에서만 통과하면 이의. 실행할 수 없는 환경이면 Summary 에 미실행이라고 적는다
- 제거 신호: 이 변경(요청·설계·규칙)으로 쓰이지 않게 된 코드·분기·설정·문서 절, 같은 사실을 두 곳에 둔 규칙, 발동한 적 없는 만약을 위한 처리, 반복해서 지켜지지 않는 규칙(문구 강화 대신 검사·hook 으로 바꾸거나 삭제)이 있는가. 있으면 `제거:` 발견(이의)으로 낸다
- 정리 후보: diff 가 닿은 파일에 이번 변경 전부터 있던 로직 중복·크기 기준 초과 파일·임시 코드나 우회는 `메모:` 대신 `정리 후보: <경로> — <내용>` 줄로 적는다. 이번 변경이 만든 것은 `제거:` 발견으로 낸다
