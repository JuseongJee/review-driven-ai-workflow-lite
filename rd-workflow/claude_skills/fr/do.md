## /fr do

여러 FR 을 한 번에 처리합니다. 대화형은 FR 을 줄기(promote 한 worktree + herdr 작업 세션)로 나눠 병렬로 띄우고, 호출 세션이 감시·발행 허가·마감을 맡습니다. 무인(`--headless`)은 고른 FR 을 `ralph_drain.sh` 엔진으로 순차 완주합니다.

호출 세션은 사람과 대화하는 이 세션입니다. 호출 세션은 기본 체크아웃(`git worktree list --porcelain` 의 첫 항목) 루트에서 이 절차를 따릅니다. 아래 명령은 모두 그 루트에서 실행합니다.

### 호출 형식

```
/fr do [--model <값>] [--effort <값>] [<slug들>]               대화형 병렬 (터미널 herdr 전용)
/fr do --headless [--finish push|merge|none] [--model <값>] [--effort <값>] [<slug들>]   무인 순차
/fr batch [<인자>]                                             별칭 — 「/fr batch 별칭」 절
```

- `<slug들>` 은 공백으로 구분한 FR short-title 입니다. 없으면 활성 FR 전체가 후보입니다. 같은 short-title 의 상세가 여러 날짜에 있으면 인덱스에 행이 있는 것(없으면 가장 늦은 날짜) 하나만 고릅니다.
- 「착수 가능한 것들 띄워」·「더 띄울 FR 없나」 처럼 대상을 지정하지 않은 요청은 `/fr do` 로 받습니다. 고르는 일까지 위임한 것으로 보고 묻지 않고 고릅니다. 고른 결과는 착수 보고 표로 보입니다. 예외는 대화형의 두 질문입니다: 띄울 줄기에 `idea` FR 이 있으면 groom 을 먼저 할지 한 번 묻고(「1. 고르기와 착수 보고 표」 4단계), 띄울 줄기가 있으면 설계 문답을 할지 회차당 한 번 묻습니다(같은 절 6단계).
- `--finish` 는 `--headless` 에서만 씁니다. 대화형에 `--finish` 가 오면 「`--finish` 는 `--headless` 와 함께만 씁니다」 와 사용법을 보이고 멈춥니다. 파일을 고치지 않습니다.
- `--model` 값은 `opus`·`sonnet`·`haiku`·`fable`·고정 모델 ID·`default` 입니다. `--effort` 값은 `low`·`medium`·`high`·`xhigh`·`max`·`ultra`·`lowest`·`highest`·`default` 입니다. 두 플래그는 이 회차에만 적용하고 다음 `/fr do` 호출에는 남지 않습니다.
  - 무인: 회차의 모든 FR 에 같게 적용합니다(「4. 무인」 절).
  - 대화형: 회차 값입니다. 줄기마다 값을 정하는 순서는 「1. 고르기와 착수 보고 표」 7단계입니다. 같은 회차의 재선정과 압축 뒤 이어 가기는 `log.md` 의 그 회차 착수 줄에서 회차 값을 되살립니다(「2. 대화형」 띄우기 5단계).
- 대화형은 터미널 herdr 에서만 돕니다. 판정 기준은 `HERDR_ENV` 가 설정되어 있고 `herdr` 명령이 있는 것입니다. 아니면 무인 순차로 갑니다. 이때 착수 보고 첫 줄 위에 「병렬 대화형은 터미널 herdr 에서만 지원 — 무인 순차로 진행」 을 적습니다. 받은 `--model`·`--effort` 는 무인 플래그로 그대로 넘깁니다. 무인 엔진은 회차에 값 하나만 쓰므로 7단계 기준표는 쓰지 않습니다.

스크립트는 모두 `rd-workflow/scripts/fr_do/` 에 있습니다.

| 스크립트 | 하는 일 |
| --- | --- |
| `pick.py` | 후보를 고르고 줄기로 묶음. `stream`·`order`·`hold`·`skip`·`stale` 줄 출력 |
| `handoff.py <spec.json> [--launch]` | 줄기 인계 파일 작성. `--launch` 면 promote 로 줄기를 띄우고 `active.tsv` 에 등록 |
| `watch.sh` | 상태가 바뀔 때만 한 줄씩 내는 감시 루프(Monitor 용) |
| `grant_check.sh <slug>` | 발행 허가 전 점검. `GRANT-OK` 또는 `HOLD` |
| `close.sh <slug>` | 기본 체크아웃 갱신, 작업 탭 닫기, `rd task list`, 감시 목록 정리. `CLOSED` 또는 `NOT-CLOSED` |
| `self_compact.sh [기준%] [대기초]` | 호출 세션 자기 압축 |
| `batch_legacy.sh` | `/fr batch` 별칭 안내와 남은 batch manifest 요약 |

상태 폴더는 `<기본 체크아웃>/rd-workflow-workspace/.lifecycle/fr-do/` 입니다. 어느 worktree 에서 스크립트를 불러도 같은 폴더를 씁니다.

| 경로 | 내용 |
| --- | --- |
| `active.tsv` | 실행 중 줄기. 한 줄 `<slug><TAB><소유 경로;…><TAB><FR stem;…>`. 3번째 칸이 없는 옛 줄은 소유 경로만 봅니다 |
| `reports/` | 줄기가 쓰는 `<slug>-question.md`(질문)·`<slug>-closing.md`(마감 보고) |
| `waves/<wave>/` | 인계 파일 `handoff-<slug>.md` 와 `promote.log` |
| `waves/closed/` | `close.sh` 가 `CLOSED` 로 끝낸 줄기의 보고 파일. 이름은 `<slug>-<YYYYMMDD-HHMM>-question.md`·`<slug>-<YYYYMMDD-HHMM>-closing.md` 입니다. 같은 slug 를 다시 써도 옛 보고를 새 보고로 알리지 않습니다 |
| `log.md` | 호출 세션의 진행 기록 |
| `watch-seen.tsv` | `watch.sh` 가 알린 보고 파일과 그 수정 시각. 감시를 다시 걸 때 이 기록과 비교합니다 |
| `headless-<YYYYMMDD-HHMMSS>.<임의 6자>` | 무인 실행(「4. 무인」 절)의 회차 로그. `mktemp` 가 회차마다 새로 만듭니다 |

이 폴더는 `.gitignore` 에 `rd-workflow-workspace/.lifecycle/fr-do/` 로 들어 있어야 합니다. 없으면 발행 허가 점검이 「미커밋 변경」 HOLD 를 냅니다.

#### 줄기의 에이전트 이름

줄기에 `herdr agent read`·`herdr agent prompt` 를 쓸 때는 slug 가 아니라 에이전트 이름을 씁니다. 이 문서의 `<에이전트 이름>` 은 모두 이 이름입니다.

- promote 는 에이전트 이름을 slug 에서 계산합니다. slug 가 32자 이하면 slug 그대로입니다. 32자를 넘으면 앞 32자이고, 끝이 `-` 면 그 `-` 를 뗍니다. 예: `promote-handoff-loses-caller-decisions` → `promote-handoff-loses-caller-dec`.
- 이름이 slug 와 다르면 promote 출력에 `promote: herdr 에이전트 이름 — <이름>` 줄이 나옵니다(`waves/<wave>/promote.log`).
- 직접 계산하려면 `bash -c '. rd-workflow/scripts/fr_do/_state.sh; fr_do_agent_name <slug>'` 를 실행합니다.
- 감시 이벤트 줄, `active.tsv`, 보고 파일 이름은 slug 를 씁니다. `watch.sh`·`close.sh` 는 이름을 스스로 계산합니다.

### 1. 고르기와 착수 보고 표

1. 후보를 고릅니다.

   ```bash
   python3 -I rd-workflow/scripts/fr_do/pick.py --mode interactive [--slugs "<s> <s>"] [--exclude "<stem> <stem>"]
   ```

   - `--exclude` 는 같은 회차 재선정에서만 씁니다. 값은 `log.md` 에서 그 회차의 `중복 착수 제외 회차=<회차> <stem…>` 줄에 있는 stem 을 모두 모은 것입니다(2절 띄우기 3단계). 처음 고를 때는 붙이지 않습니다.

   - 무인이면 `--mode headless` 입니다. 무인의 다음 단계는 「4. 무인」 절입니다.
   - 동시 줄기 상한은 `workflow.json` 의 `fr_do_max_streams`(없으면 4)입니다. `--max-streams N` 으로 이번 호출만 바꿀 수 있습니다.
   - rc 2 면 실행 불가입니다. stderr 전문을 사용자에게 보이고 멈춥니다. 흔한 원인은 `--slugs 에 없는 FR: <s>`(slug 오타), 관계 판정 불가, 상태 폴더를 찾지 못함입니다.
2. 출력 줄을 읽습니다. 순서는 `stream` → `hold` → `skip` → `stale` 입니다(무인은 `order` → `skip`).

   | 줄 | 뜻 |
   | --- | --- |
   | `stream<TAB><번호><TAB><stem,stem><TAB><소유 경로;…>` | 함께 띄울 줄기. 같은 파일을 고치는 FR 을 최대 3건 묶음 |
   | `hold<TAB><stem><TAB><사유>` | 이번에는 띄우지 않음. 사유는 `실행 중 줄기 <slug> 의 FR`·`겹침 보류 — <FR> 와 같은 파일, 줄기당 3건 상한`·`실행 중 줄기 <slug> 와 겹침`·`동시 줄기 상한 <N>` |
   | `skip<TAB><stem><TAB><사유>` | 대상이 아님. 사유는 `상태 <status>`, readiness 판정(선행 FR 미완 등), `이번 회차 중복 착수`(`--exclude` 로 뺌). `--slugs` 로 지정한 FR 이 이미 `done` 이면 `상태 done` 으로 나옵니다 |
   | `stale<TAB><slug><TAB>로컬 브랜치 fr/<slug> 없음` | 대화형 전용. `active.tsv` 에 남은 끝난 줄기의 낡은 줄. 이 줄의 FR·소유 경로는 보류에 쓰지 않았고 동시 상한에도 세지 않았습니다 |
   | `order<TAB><stem><TAB><readiness>` | 무인 전용. 우선순위 순 실행 후보 |

   - `stale` 줄은 줄기를 되돌렸거나(`promote_rollback.sh`) 정리 전에 브랜치가 지워진 줄기입니다. 이번 `/fr do` 호출에서 아직 정리를 시도하지 않은 slug 마다 아래 순서로 정리합니다.
     1. `reports/<slug>-closing.md` 가 있고, `log.md` 에서 그 slug 가 들어 있는 가장 최근 착수 줄(2절 띄우기 5단계) 뒤에 그 slug 의 마감 줄(3절 6단계)이 없으면 아직 처리하지 않은 마감 보고입니다. 같은 slug 를 예전에 쓴 줄기의 마감 줄은 새 착수 줄보다 앞에 있으므로 세지 않습니다. 「3. 마감과 재선정」 1~7단계로 처리합니다. 그 2단계의 `close.sh` 에는 `--stale` 을 붙입니다. 8단계 재선정은 하지 않고 이 고르기로 돌아옵니다.
     2. 그 밖이면 `reports/<slug>-closing.md` 는 이미 처리한 보고입니다(앞선 정리가 `NOT-CLOSED` 로 끝나 남음). `reports/<slug>-question.md` 만 있으면 질문 요지를 사용자에게 보입니다(줄기가 끝났으므로 답을 보내지 않습니다). 그다음 `bash rd-workflow/scripts/fr_do/close.sh <slug> --stale` 로 정리합니다. `close.sh` 는 `CLOSED` 면 그 줄기의 보고 파일을 `waves/closed/` 로 옮깁니다. `--stale` 은 탭을 닫지 않습니다(`탭 건드리지 않음: <slug>` 줄). 낡은 줄기의 세션은 이미 끝나 있고, 에이전트 이름으로 찾은 탭은 같은 이름을 쓰는 다른 줄기의 것일 수 있기 때문입니다. 그 사이 로컬 브랜치 `fr/<slug>` 가 다시 생겼으면 목록을 건드리지 않고 `NOT-CLOSED` 로 끝냅니다.
     3. 정리 결과(`CLOSED <slug>` 또는 `NOT-CLOSED …` 줄)와 `close.sh` 출력의 `rd task list` 줄(다른 작업의 `정리`·`보류`·`탭 닫음` 줄 포함, 아래 참고)을 「정리한 낡은 줄」 로 한 줄씩 정리 직후 사용자에게 보입니다. 뒤 단계(groom 중단, 띄울 줄기 없음, 착수)가 어떻게 끝나든 이 보고는 이미 나간 것입니다.
     4. 정리를 하나라도 시도했으면 1단계 `pick.py` 를 같은 인자로 다시 실행하고 그 출력으로 이 단계부터 다시 읽습니다. `close.sh` 의 `git pull`·`rd task list` 가 후보와 진행 상태를 바꿀 수 있기 때문입니다. 다시 나온 `stale` 줄 가운데 이번 호출에서 이미 정리를 시도한 slug 는 다시 정리하지 않습니다.
   - `close.sh` 가 부르는 `rd task list` 는 이 줄기만이 아니라 저장소 전체의 정리 대기 작업(worktree·브랜치)을 정리합니다. 출력의 `정리`·`보류`·`탭 닫음` 줄은 다른 작업의 것일 수 있으므로 그 줄도 「정리한 낡은 줄」 에 그대로 옮깁니다.
3. 기계가 판정하지 않는 것을 호출 세션이 봅니다. `stream`·`order` 의 FR 마다 상세 파일을 읽고 아래를 확인합니다.
   - `revisit when` 이 아직 오지 않았으면 뺍니다.
   - 해결 흔적: `bash rd-workflow/scripts/fr_related_history.sh <상세 파일>` 과 `bash rd-workflow/scripts/check_fr_related_files_existence.sh <상세 파일>` 을 봅니다. 신호는 참고입니다. 이미 해결된 것으로 보이면 코드를 열어 확인한 뒤 뺍니다. 확인 없이 신호만으로 빼지 않습니다.
   - 뺀 FR 이 줄기의 유일한 FR 이면 그 줄기를 띄우지 않습니다. 줄기 안 한 건만 빼면 소유 경로에서 그 FR 만의 경로를 뺍니다.
4. **idea FR 확인 (대화형만)**: 3단계를 거친 뒤 띄울 줄기에 상세 `status` 가 `idea` 인 FR 이 있으면, 그 FR 목록(short-title 과 summary 한 줄)을 보이고 한 번 묻습니다. 백로그의 다른 `idea` FR 은 묻는 조건이 아닙니다. 띄울 줄기에 `idea` FR 이 없으면 묻지 않습니다.

   | 선택 | 얻는 것 | 잃는 것 |
   | --- | --- | --- |
   | groom 먼저 | 검증하지 않은 FR 로 줄기를 띄워 작업 하나를 통째로 버리는 일을 막습니다. dropped·parked 로 빠진 FR 만큼 줄기 묶음이 바뀝니다 | 띄우기 전에 FR 마다 문답 시간이 듭니다 |
   | 그대로 띄우기 | 지금 바로 띄웁니다 | 줄기가 착수한 뒤에야 FR 이 필요 없거나 아직 이르다는 것이 드러날 수 있습니다 |

   - groom 먼저: groom 이 바꿀 경로(`rd-workflow-workspace/backlog/FUTURE_REQUESTS.md`, `rd-workflow-workspace/backlog/FUTURE_REQUESTS_PARKED.md`, 대상 FR 의 상세 파일, `rd-workflow-workspace/raw-captures/`)에 미커밋 변경이 있는지 먼저 봅니다(`git status --porcelain -- <경로들>`). 있으면 groom 결과와 사용자 변경이 한 커밋에 섞이므로 groom 을 시작하지 않습니다. 그 파일 목록과 「이 파일의 변경을 커밋하거나 치운 뒤 `/fr do` 를 다시 부르십시오」 를 보이고 끝냅니다. 깨끗하면 그 FR 들로 `/fr groom <slug들>` 절차(`rd-workflow/claude_skills/fr/groom.md` 일괄 모드)를 수행하고, 끝나면 아래 순서로 갑니다.
     1. groom 결과를 기본 브랜치에 커밋합니다. 줄기는 promote 가 로컬 기본 브랜치 tip 에서 만들므로, 커밋하지 않으면 줄기는 groom 전의 상세(`idea` 상태와 옛 `request seed`)를 받고, 남은 미커밋 변경은 발행 허가 점검의 「미커밋 변경」 HOLD 가 됩니다. 쓰기 전에 `MERGE_HEAD` 가 없는지 확인합니다. `git status --porcelain -- <위 경로들>` 에 나온 파일만 `git add -- <파일들>` 로 올리고, 같은 파일 목록을 `git commit -m "chore: FR groom 결과 반영 — <slug들>" -- <파일들>` 처럼 경로로 한정해 커밋합니다. 경로를 빼고 `git commit` 을 부르면 사용자가 따로 stage 해 둔 무관한 변경까지 들어가므로 반드시 경로를 붙입니다. 바뀐 파일이 없으면(모두 건너뛰기) 커밋하지 않습니다. `git add`·`git commit` 이 실패하면 새 줄기를 띄우지 않습니다. 실패 출력과 「groom 결과가 커밋되지 않아 착수를 멈췄습니다」 를 보이고 끝냅니다.
     2. groom 을 「중단」 으로 끝냈으면 새 줄기를 띄우지 않습니다. groom 결과 요약표 아래에 「groom 을 중단해 이번 `/fr do` 의 착수를 멈췄습니다 — 다시 고르려면 `/fr do` 를 부르십시오」 를 보이고 끝냅니다. 이미 실행 중인 줄기의 감시는 그대로 둡니다.
     3. 끝까지 마쳤으면 1단계 `pick.py` 부터 같은 인자로 다시 고릅니다. 이 질문을 이미 한 FR(건너뛰었거나 `idea` 유지로 끝난 FR 포함)은 다시 묻지 않고 그대로 띄웁니다. 다시 고른 결과 띄울 줄기에 아직 묻지 않은 `idea` FR 이 있으면(앞 FR 이 빠져 hold 였던 FR 이 올라온 경우) 그 FR 만으로 이 질문을 다시 합니다. 물은 FR 은 늘기만 하므로 반복은 끝납니다.
   - 그대로 띄우기: `idea` FR 을 포함해 다음 단계로 갑니다.
5. 띄울 줄기가 0개면 「띄울 줄기 없음」 과 뺀 FR 표(8단계)만 보이고 끝냅니다. 6단계 질문을 하지 않습니다.
6. **설계 문답 확인 (대화형만)**: 띄울 줄기가 있으면 이 회차에 설계 문답을 할지 한 번 묻습니다. 회차는 이 `/fr do` 호출 하나입니다. 3절 8단계의 재선정은 같은 회차이므로 다시 묻지 않고 이 답을 이어 씁니다.

   | 선택 | 얻는 것 | 잃는 것 |
   | --- | --- | --- |
   | 설계 문답 | 줄기가 코드를 읽은 뒤 설계 질문을 자기 탭에서 사용자에게 직접 묻습니다. 사용자가 다르게 생각하는 결정이 spec/plan review 여러 바퀴 뒤가 아니라 착수 직후에 드러납니다 | 줄기마다 탭에서 답해야 하고, 답할 때까지 그 줄기는 멈춥니다 |
   | 그냥 진행 | 지금처럼 줄기가 설계 질문을 스스로 정하고 끝까지 갑니다 | 줄기가 정한 설계가 사용자 생각과 다르면 리뷰 뒤에야 드러납니다 |

   - 설계 문답은 사용자가 고른 회차에만 도는 opt-in 입니다. `core.md` 「실행 모드 규칙」 과 계정 규칙의 「설계·스펙 승인 대기 생략」 은 바꾸지 않고, 인계 파일의 「설계 문답」 절이 그 줄기에서 이 규칙보다 우선한다고 적습니다(`handoff.py` 가 씀).
   - 물을 것이 없는 줄기는 묻지 않고 진행합니다.
7. **줄기별 모델·effort (대화형만)**: 줄기마다 작업 세션의 모델·effort 를 정합니다. 묻지 않습니다. 칸마다 아래 순서에서 처음 값이 있는 것을 씁니다.
   1. 사용자의 줄기별 지시(예: 「이 줄기는 fable 로」). 이 회차의 대화에서 받은 지시입니다.
   2. 회차 플래그 `--model`·`--effort`.
   3. 아래 기준표.

   | 줄기 성격 | 모델 | effort |
   | --- | --- | --- |
   | 문서·skill 문구만 바꿈(스크립트·테스트 변경 없음) | `opus` | `medium` |
   | 스크립트를 바꿈(기본) | `opus` | `high` |
   | lifecycle·리뷰·발행 엔진(`rd-workflow/scripts/lifecycle/`·리뷰 어댑터·`archive.sh`·발행 큐)을 바꿈, FR 3건을 묶음, 설계가 큰 `feature` 중 하나라도 해당 | `opus` | `xhigh` |

   - 성격은 FR 상세(`kind`, `request seed`, `related files`)와 `stream` 줄의 소유 경로로 판단합니다. 두 행에 걸치면 높은 행을 씁니다.
   - `fable` 은 기준표에 넣지 않습니다. 사용자가 지시했을 때만 씁니다(Opus 의 두 배 비용).
   - 정한 값은 2절 spec JSON 의 줄기 항목 `model`·`effort` 에 적습니다. 값이 `handoff.py` 가 받는 범위 밖이면 띄우기 전에 rc 2 로 멈춥니다.
8. 착수 보고 표를 사용자에게 보입니다. 4·6단계의 질문 말고는 질문하지 않고 바로 다음 단계로 갑니다. 표 위 첫 줄에 6단계 답을 `설계 문답: 예` 또는 `설계 문답: 아니오(그냥 진행)` 로 적습니다. 회차 플래그를 받았으면 둘째 줄에 `회차 값: --model <값> --effort <값>`(받은 것만)을 적습니다.

   | 줄기 | FR | 소유 파일 | 모델·effort |
   | --- | --- | --- | --- |
   | `<slug>` | `<short-title>`, … | `<경로>`, … | `opus·high`(근거: 기준표 「스크립트를 바꿈」 / 회차 플래그 / 사용자 지시) |

   그 아래 「뺀 FR」 표에 `hold`·`skip` 줄과 호출 세션이 뺀 FR 을 모두 적습니다.

   | 뺀 FR | 이유 |
   | --- | --- |
   | `<short-title>` | `pick.py` 사유 그대로, 또는 호출 세션이 뺀 근거(revisit when 미도래, 해결 흔적과 확인한 파일) |

### 2. 대화형: 띄우기와 감시

#### 띄우기

1. 줄기 slug 를 정합니다. FR 1건이면 그 short-title 을 씁니다. 여러 건이면 공통 주제를 담은 짧은 이름을 씁니다. slug 는 `^[A-Za-z0-9._-]+$` 이고 `.`·`..` 가 아니어야 합니다. 이미 있는 브랜치 `fr/<slug>`, `active.tsv` 에 남은 줄의 slug, `reports/<slug>-*.md` 가 남은 slug 와 겹치지 않게 합니다(남은 보고가 새 줄기의 보고로 읽히지 않게).
2. spec JSON 을 scratchpad 에 씁니다. 형식은 `handoff.py` 머리 주석이 정본입니다.
   - `wave` 는 `YYYY-MM-DD-<차수>` 처럼 이번 착수를 가리키는 이름입니다. 상태 폴더에 `waves/<wave>/` 가 아직 없는 이름을 고릅니다. 이 이름은 회차 식별자(5단계의 `회차`)로도 쓰므로 다른 회차와 겹치면 안 됩니다. `handoff.py` 가 이 폴더를 원자적으로 만들어 예약하므로, 다른 호출이 같은 이름을 먼저 썼으면 3단계에서 「wave 가 이미 있습니다」 로 멈춥니다.
   - `why` 에 사용자 지시를 따옴표로 옮깁니다.
   - `owns` 는 사람이 읽는 소유 파일 문자열이고, `owns_paths` 는 `stream` 줄의 소유 경로를 배열로 옮긴 것입니다.
   - 1절 6단계에서 설계 문답을 골랐으면 최상위에 `"design_qa": true` 를 넣습니다. 그냥 진행이면 넣지 않습니다.
   - 줄기 항목에 1절 7단계에서 정한 `"model"`·`"effort"` 를 넣습니다.
   - `notes` 에는 FR 상세를 사실로 받지 말고 재현부터 할 지점, 실제 배포·원격 조작 금지 같은 줄기별 주의, 「검증은 프로젝트 규칙의 검증 절차를 따름」 을 적습니다.
3. 띄웁니다.

   ```bash
   python3 -I rd-workflow/scripts/fr_do/handoff.py <spec.json> --launch
   ```

   - 줄마다 `<slug>: promote rc=<rc> <요약 줄>` 이 나옵니다. 요약 줄은 promote 출력의 마지막 `promote: 세션 기동 …` 줄입니다. promote 는 기동이 실패해도 rc 0 을 냅니다. 그래서 `handoff.py` 는 rc 0 이고 기동 결과가 `failed` 가 아닌 줄기만 `active.tsv` 에 넣습니다.

     | 요약 줄 | 처리 |
     | --- | --- |
     | `promote: 세션 기동 결과 — ok (…)` | 정상입니다. 감시 대상입니다 |
     | `promote: 세션 기동 성공 / 상태 기록 미완료 — …` | 줄기는 떴습니다. 감시 대상입니다. 「복구:」 뒤의 명령을 실행합니다 |
     | `promote: 세션 기동 결과 — unknown (…)` | 세션이 떴는지 모릅니다. `bash rd-workflow/scripts/rd task resolve-launch <slug>` 로 확인합니다. 떠 있으면 감시 대상으로 둡니다. 떠 있지 않으면 사용자에게 알리고 `active.tsv` 에서 그 줄을 지웁니다(아래 명령) |
     | `promote: 세션 기동 결과 — failed (…)` | 세션이 없습니다. `active.tsv` 에 들어가지 않았습니다. 사용자에게 사유(괄호 안)를 알립니다 |

   - 그 다음 줄에 `<slug>: 다음 기동에 사용할 모델 — … · effort — … (출처: …)` 가 나옵니다. promote 가 실제로 넘긴 값과 출처입니다. 출처가 `RD_SESSION_MODEL`·`RD_SESSION_EFFORT` 가 아니거나 값이 착수 보고 표와 다르면(값 무효·CLI 미지원) `promote.log` 의 그 줄기 구간에서 `⚠️` 줄을 읽어 6단계 보고에 함께 적습니다.

     `active.tsv` 에서 첫 칸이 `<slug>` 인 줄을 지우는 명령입니다.

     ```bash
     a=rd-workflow-workspace/.lifecycle/fr-do/active.tsv
     awk -F'\t' -v s="<slug>" '($1 "") != (s "")' "$a" > "$a.tmp" && mv "$a.tmp" "$a"
     ```

   - 줄기 줄의 `promote rc=` 가 0 이 아니면 `waves/<wave>/promote.log` 를 읽고 사유를 사용자에게 알립니다. 이 줄기는 `active.tsv` 에 들어가지 않으며 감시 대상이 아닙니다.
     비교는 문자열입니다. `$1!=s` 로 쓰면 awk 가 숫자 모양 이름(`01`·`1`)을 같게 보아 다른 줄을 지웁니다.

   - 줄기 줄이 `<slug>: promote rc=1 promote: 중복 착수 — …` 이면 중복 착수로 멈춘 것입니다. 그 아래 두 칸 들여쓰기 줄(`<slug>:   …`)이 사유와 다음 행동입니다. 이 줄기는 `active.tsv` 에 들어가지 않았습니다.
     - 사유와 다음 행동을 사용자에게 알립니다.
     - 그 줄기의 spec `frs` 를 이번 회차에서 뺍니다. `log.md` 에 `중복 착수 제외 회차=<회차> <stem> <stem>` 줄을 덧붙입니다. `<회차>` 는 5단계의 회차 값입니다. 같은 회차의 재선정(3절 8단계)은 이 줄의 stem 을 `pick.py --exclude` 로 넘깁니다.
   - `<slug>: promote: 중복 확인 경고` 줄은 6단계 보고에 함께 적습니다.
   - rc 0 인데 「기동 결과 줄 없음」 이면 `active.tsv` 에는 들어갔습니다. `promote.log` 의 그 줄기 구간(`=== <slug>` 아래)을 읽고, 세션이 없으면 사용자에게 알리고 위 명령으로 그 줄을 지웁니다.
   - 아래 네 경우는 `handoff.py` 자체가 줄기 줄 없이 끝난 것입니다. 어느 줄기도 띄우지 않았으므로 `promote.log` 를 읽지 않고, 4단계 감시와 5단계 착수 줄로 넘어가지 않습니다.
   - rc 2 와 「slug 값이 올바르지 않습니다」·「wave 값이 올바르지 않습니다」 는 spec JSON 의 이름 문제입니다. 고쳐서 다시 실행합니다.
   - rc 2 와 「wave 가 이미 있습니다」 는 다른 회차가 그 wave 이름을 먼저 썼다는 뜻입니다. 차수를 올린 새 이름으로 spec JSON 을 고쳐 다시 실행합니다. 이 호출이 처음 띄우는 wave 라면 5단계의 `회차` 도 새 이름입니다.
   - rc 2 와 「세션 모델·effort 값이 올바르지 않습니다」 는 줄기 항목의 `model`·`effort` 값 문제입니다. stderr 의 `<slug>: <model|effort> '<값>'` 줄과 「어느 줄기도 띄우지 않았습니다」 를 사용자에게 그대로 알립니다. 값이 회차 플래그나 사용자 지시에서 왔으면 사용자에게 바른 값을 받아 1절 7단계부터 다시 정합니다. 기준표에서 왔으면 기준표 값으로 고쳐 다시 실행합니다. 「판정하지 못했습니다」 면 `model_select.sh` 를 읽지 못한 것이므로 그 메시지를 알리고 멈춥니다.
   - rc 1 과 `FR 상세 없음: <경로>` 는 spec JSON 의 `frs` 에 없는 stem 이 있다는 뜻입니다. 이때는 어느 줄기도 띄우지 않았습니다. stem 을 `rd-workflow-workspace/backlog/items/` 의 파일 이름에 맞게 고쳐 다시 실행합니다.
4. 감시를 겁니다. Monitor 에 아래 명령을 `timeout_ms` 1800000 으로 겁니다. **만료 알림이 올 때마다 다시 겁니다.** 이미 알린 보고는 다시 걸어도 알리지 않습니다. 감시가 꺼져 있던 동안(첫 기동 전·다시 걸기 전) 쓰인 보고는 다시 걸 때 알립니다. 감시는 도는 동안 발행 큐에 생존 표시를 남깁니다. 다시 걸지 않아 5분이 지나면 줄기의 `rd publish request`·`wait` 가 「호출 세션의 감시가 없습니다」 경고를 내고, 줄기가 그 경고를 사용자에게 알립니다.

   ```bash
   bash rd-workflow/scripts/fr_do/watch.sh 2>&1 | grep --line-buffered -E "^(STREAM|QUEUE|CTX|REPORT)|rror|No such"
   ```

5. `log.md` 에 착수 줄(`회차: <첫 wave>`, wave, 줄기별 FR, 인계 폴더, `설계 문답: 예|아니오`, `회차 값: --model <값> --effort <값>|없음`, 줄기별 `모델·effort`)을 덧붙입니다.
   - `회차` 는 이 `/fr do` 호출이 처음 띄운 wave 이름입니다. 같은 회차의 재선정은 새 wave 를 쓰지만 `회차` 는 첫 wave 그대로 적습니다.
   - 착수 줄의 줄기 목록에는 이번에 실제로 뜬 줄기(3단계에서 `active.tsv` 에 남은 줄기)만 적습니다. 기동 실패·rc≠0 줄기는 적지 않습니다. `unknown` 은 `resolve-launch` 로 떠 있다고 확인한 뒤에만 적습니다. 그래야 다른 회차가 같은 slug 로 착수를 시도했다가 실패해도 그 slug 의 회차가 바뀌지 않습니다.
   - 재선정(3절 8단계)과 압축 뒤 이어 가기는 회차 값을 이렇게 되살립니다: 이벤트·마감 보고가 온 줄기 slug 가 들어 있는 가장 최근 착수 줄에서 `회차` 를 읽고, 같은 `회차` 의 가장 최근 착수 줄에서 설계 문답 값과 회차 값을 읽습니다. `log.md` 는 여러 회차가 함께 쓰므로 회차를 가리지 않고 마지막 착수 줄을 읽지 않습니다.
   - 사용자의 줄기별 지시는 그 줄기에만 적용하므로 다음 줄기에 이어 쓰지 않습니다.
6. 사용자에게 보고합니다: 띄운 줄기 수, 줄기마다 적용된 모델·effort(3단계의 적용 줄), 줄기마다 착수 표시 상태, 실패한 줄기와 사유, 「감시 중 — 이벤트마다 보고합니다」.
   - 줄기마다 착수 표시 상태는 `handoff.py` 가 낸 `<slug>: 착수 표시 상태 — <상태>` 줄을 그대로 옮깁니다. `<slug>: promote: 중복 확인 경고 — 같은 작업의 다른 흔적` 줄이 있으면 그 줄과 발견 줄을 「중복 흔적」 으로 따로 적습니다.

#### 감시 이벤트 처리

이벤트마다 사용자에게 한두 줄로 보고합니다. 「할 일 없음」 이면 보고를 생략해도 됩니다.

| 이벤트 | 호출 세션 행동 | 사용자에게 보일 것 |
| --- | --- | --- |
| `STREAM <s> idle`·`STREAM <s> done` | `herdr agent read <에이전트 이름> --source visible` 로 화면을 봅니다. 백그라운드 작업을 기다리는 중이면 둡니다. 줄기가 사람 입력 없이 멈춰 있고 보고 파일도 없으면 화면 내용을 확인해 다음 이벤트를 기다립니다. `reports/<s>-question.md` 의 첫 줄이 「사용자 직접 답변 — 호출 세션은 답하지 않음」 이면 사용자 답을 기다리는 중입니다. 멈춤으로 보지 않습니다. 첫 줄이 「사용자 직접 답변 — 답변 완료」 면 대기가 끝났으므로 이 판정에 쓰지 않습니다 | 기다리는 중이면 생략. 멈춘 것으로 보이면 「`<s>` 가 멈춰 있습니다 — <화면 요지>」 |
| `STREAM <s> blocked` | 다이얼로그(도구 권한·선택 창)가 떠 있습니다. **입력을 보내지 않습니다**(승인은 사람). 화면을 읽고 무엇을 기다리는지 확인합니다 | 생략. 사용자는 herdr 탭 상태로 직접 봅니다. 무엇을 기다리는지 `log.md` 에만 남깁니다 |
| `STREAM <s> gone` | 작업 세션이 없어졌습니다. `reports/<s>-closing.md` 가 있으면 마감으로 갑니다. 없으면 `git worktree list` 로 작업 worktree 를 찾고 그 안의 `bash rd-workflow/scripts/rd task status` 로 상태를 확인합니다. 다시 띄우지 않습니다. 사용자가 다시 띄우지 않기로 하면 감시 목록에서 뺍니다(아래 「다시 띄우지 않는 줄기」) | 「`<s>` 세션이 마감 보고 없이 끝났습니다」, 작업 상태, worktree 경로, 인계 파일 경로. 다시 띄울지는 사용자가 정합니다 |
| `CTX <s> N% <상태> @<구간>` | 줄기의 컨텍스트가 85% 이상입니다. `<상태>` 는 `idle`·`done`·`working` 중 하나이고, `<구간>` 은 이번 고비율 구간(85% 아래로 내려가기 전까지)의 ID 입니다. 감시는 한 구간에 이 이벤트를 한 번만 냅니다(감시를 다시 걸어도 같음). 감시가 줄을 낸 직후 강제 종료되면 같은 구간 ID 로 한 번 더 올 수 있으므로, `log.md` 에 같은 `<구간>` 의 처리 줄이 이미 있으면 압축을 다시 보내지 않고 넘어갑니다. 처리 줄이 없고 발행이나 마감 보고 중이 아니면 `herdr agent prompt <에이전트 이름> "/compact"` 를 보냅니다. 발행·마감 중이면 보내지 않습니다(발행이 끝나면 그 세션은 마감함). `working` 이면 보낸 `/compact` 는 입력 대기열에 들어가 지금 턴이 끝난 뒤 돕니다. 진행 중인 도구 호출(subagent 대기 포함)은 멈추지 않습니다. 처리 결과를 `log.md` 에 `CTX <s> @<구간> — 압축 보냄 <시각>` 또는 `CTX <s> @<구간> — 보내지 않음(<사유>) <시각>` 으로 남깁니다(같은 구간의 긴급 이벤트가 이 줄을 찾음). `idle` 화면을 읽을 때 80% 대이고 다음 단계가 리뷰처럼 길면 이벤트 없이 먼저 보내도 됩니다 | `idle`·`done`: 「`<s>` 컨텍스트 N% — 압축을 보냈습니다」. `working`: 「`<s>` 컨텍스트 N% — 압축을 보냈습니다. 지금 턴이 끝나면 압축됩니다」. 발행 중: 「발행 중이라 압축하지 않았습니다」 |
| `CTX <s> N% <상태> 긴급 @<구간>` | 줄기의 컨텍스트가 100% 이상입니다. 감시는 같은 `<구간>` 의 85% 이벤트를 낸 뒤에만 이 이벤트를 냅니다. `log.md` 에서 `CTX <s> @<구간>` 처리 줄(같은 구간 ID)을 찾습니다. 그 줄이 있으면 **이 이벤트에서는 `/compact` 를 보내지 않습니다**(대기열에 두 번 들어가면 압축이 두 번 돕니다). 알리기만 하고, 멈출지는 사용자가 그 탭에서 정합니다. 입력을 보내 멈추게 하지 않습니다. 그 줄이 없으면(85% 이벤트를 받고 처리 줄을 남기기 전에 끊김) 위 행처럼 처리하고 처리 줄을 남깁니다 | 처리 줄이 압축 보냄이고 `working` 이면: 「`<s>` 컨텍스트 N% (긴급) — 압축을 보냈지만 지금 턴이 끝나야 압축됩니다. 급하면 그 탭에서 Esc 로 멈춘 뒤 `/compact` 를 입력하십시오. 멈추면 진행 중인 도구 호출(subagent 대기 포함)이 끊길 수 있습니다」. 처리 줄이 압축 보냄이고 `idle`·`done` 이면: 「`<s>` 컨텍스트 N% (긴급) — 압축을 보냈습니다」. 처리 줄이 보내지 않음이면: 「`<s>` 컨텍스트 N% (긴급) — <사유>로 압축하지 않았습니다」. 처리 줄이 없었으면 위 행의 문구 앞에 「`<s>` 컨텍스트 N% (긴급) — 85% 알림의 처리 기록이 없어 지금 처리했습니다」 를 붙입니다 |
| `QUEUE 조회 실패 (rc=N): <오류 첫 줄>` | 감시가 발행 큐를 읽지 못합니다. 그동안 감시는 생존 표시를 남기지 않으므로, 5분이 지나면 줄기의 `rd publish request`·`wait` 가 감시 없음 경고를 냅니다. `bash rd-workflow/scripts/lifecycle/publish_queue.sh status` 를 직접 실행해 오류를 확인하고 원인을 고칩니다. 원인을 모르면 허가하지 않습니다. 조회가 회복되면 감시가 처리할 큐 줄을 `QUEUE` 로 다시 내므로(실패 전과 같은 내용이어도) 그 이벤트로 허가 점검을 이어 갑니다 | 「발행 큐를 읽지 못합니다 — 그동안 발행 허가가 멈춥니다」 와 오류 줄 원문, 확인한 원인. 회복 뒤 첫 `QUEUE` 에서 「발행 큐 조회가 회복됐습니다」 |
| `QUEUE <큐 줄;…>` | `요청됨` 줄이 있으면 「HOLD 처리」 절의 점검을 합니다. `rd publish next` 는 가장 앞의 `요청됨` 요청을 허가하므로 그 요청의 slug 로 `grant_check.sh` 를 부릅니다. `GRANT-OK` 면 `bash rd-workflow/scripts/rd publish next` 를 실행하고 「허가했습니다: <slug>」 를 확인합니다. `rd publish next` 가 「허가하지 않습니다 — <사유>」 또는 「허가할 요청 없음」 을 내면 허가하지 않은 것입니다. 사유를 기록하고 다음 `QUEUE` 이벤트를 기다립니다. `HOLD` 면 허가하지 않습니다. `사용자 승인 대상` 줄은 호출 세션이 허가하지 않습니다. 사용자에게 승인을 묻고, 승인하면 `bash rd-workflow/scripts/rd publish approve <s>` 를 실행합니다. `실패`·`충돌` 줄이면 `bash rd-workflow/scripts/rd publish status` 를 읽습니다 | 허가: 「`<s>` 발행을 허가했습니다」. 허가 거부: `rd publish next` 출력 원문. HOLD: 사유 목록과 처리 내용. 사용자 승인 대상: 큐 줄 원문과 「승인하면 `rd publish approve <s>` 를 실행합니다」. 실패·충돌: 큐 줄 원문과 다음 행동 |
| `REPORT …/<s>-question.md` | 줄기의 질문입니다. 파일을 읽습니다. 첫 줄이 「사용자 직접 답변 — 호출 세션은 답하지 않음」 이면 설계 문답 질문입니다. 대신 답하지 않고 `herdr agent prompt` 도 보내지 않습니다. 질문 요지와 「사용자 탭 안내」 를 `log.md` 에 남깁니다. 첫 줄이 「사용자 직접 답변 — 답변 완료」 면 사용자가 탭에서 답한 것입니다. 답하지 않고 사용자에게 알리지도 않으며 `log.md` 에 「답변 완료」 만 남깁니다. 그 밖의 질문은 「위임 답변 경계」 로 답을 정합니다. 답할 수 있으면 `herdr agent prompt <에이전트 이름> "<한 문장 답>"` 으로 보내고 답과 근거를 `log.md` 에 남깁니다. 사용자 판단이 필요하면 보내지 않고 사용자에게 묻습니다. 사용자 답을 받으면 그 답을 같은 방법으로 보냅니다 | 설계 문답 질문과 답변 완료는 생략합니다. 사용자는 herdr 탭에서 질문을 직접 보고 답합니다. 대신 답했으면 답과 근거(수치·파일) 한두 줄. 사용자 판단이 필요하면 질문 원문과 선택지마다 얻는 것·잃는 것 |
| `REPORT …/<s>-closing.md` | 마감 보고입니다. 「3. 마감과 재선정」 으로 갑니다 | 마감 결과(3절 7단계) |

- 다시 띄우지 않는 줄기: 작업을 폐기할지 남길지는 사용자가 정합니다.
  - 폐기하면 프로젝트의 롤백 절차(기본 체크아웃에서 `bash rd-workflow/scripts/lifecycle/promote_rollback.sh --task <s>`)로 worktree 와 브랜치 `fr/<s>` 를 없앤 뒤 `bash rd-workflow/scripts/fr_do/close.sh <s>` 를 부릅니다.
  - 남기면 worktree 와 브랜치는 그대로 두고, 「띄우기」 절의 `active.tsv` 줄 삭제 명령으로 `<s>` 줄만 지웁니다. 이 줄기의 소유 파일과 FR 은 다음 재선정부터 보류되지 않습니다.
- `CTX` 이벤트와 「호출 세션의 압축」 은 Claude Code 상태줄에 `NN% NNNk/` 형식의 컨텍스트 표시가 있어야 동작합니다. 그 표시가 없으면 `CTX` 이벤트가 나오지 않고 `self_compact.sh` 는 `SKIP` 으로 끝납니다. 감시는 화면의 입력줄(`❯`) 아래에서만 이 표시를 찾으므로, 입력줄이 화면에 보이지 않는 동안에는 `CTX` 이벤트를 내지 않습니다. 같은 체크아웃에서 회차 여럿이 감시를 돌리면 먼저 `CTX` 를 맡은 감시 하나만 `CTX` 를 내므로, 그 감시를 건 호출 세션만 `CTX` 이벤트를 받습니다. 그 감시가 끝나면 남은 감시가 이어 냅니다.
- `herdr agent prompt` 는 줄기 세션의 입력창으로 갑니다. 사람이 호출 세션에 치는 글과 섞이지 않습니다.
- 줄기는 호출 세션 입력창에 글을 보내지 않고 `reports/` 에 파일을 씁니다. 옛 인계로 띄운 줄기가 입력창으로 보내 오면 그 문장만 골라 읽습니다.
- 발행이 도는 동안에는 기본 체크아웃에 쓰지 않습니다. 호출 세션이 직접 발행 중이면 허가를 그 뒤로 미룹니다.
- `rror`·`No such` 줄은 감시 스크립트 오류입니다. 원문을 사용자에게 보이고, 원인을 고친 뒤 감시를 다시 겁니다.

#### 위임 답변 경계

- 첫 줄이 「사용자 직접 답변 — 호출 세션은 답하지 않음」 인 질문은 되돌리기 쉬워도 대신 답하지 않습니다. 사용자가 그 줄기 탭에서 답합니다.
- 되돌리기 어려운 효과가 없으면 줄기 권장안을 따릅니다. 따르기 전에 근거(수치·파일)를 직접 확인합니다.
- 되돌리기 어려운 선택(merge·폐기, 데이터 삭제, 외부 발행, 요구사항이 바뀌는 범위 변경, 제품 방향)은 대신 답하지 않습니다. 사용자에게 질문 원문과 선택지를 보이고 답을 받습니다.
- 등급: AI 하향은 허용합니다. 되돌리기 어려운 효과가 있으면 `full` 로 고정합니다.
- 범위 밖 파일 수정 요청은 그 파일이 다른 줄기 소유가 아니고 FR 목적에 필요할 때만 허가합니다. 다른 줄기 소유면 거절하고 마감 보고에 적게 합니다.
- 답과 근거는 `log.md` 에 남깁니다.

#### HOLD 처리

`grant_check.sh <s>` 가 `HOLD` 를 내면 첫 줄 `HOLD <s>` 아래 `  - <사유>` 줄을 읽습니다.

`grant_check.sh` 출력에 `GRANT-OK` 도 `HOLD` 도 없거나, `close.sh` 출력에 `CLOSED` 도 `NOT-CLOSED` 도 없으면 스크립트가 판정 전에 끝난 것입니다. 허가·정리를 하지 않고 출력 전문을 사용자에게 보인 뒤 멈춥니다.

| 사유 | 쪽 | 행동 |
| --- | --- | --- |
| `메인 체크아웃에 병합 진행 중(MERGE_HEAD)` | 기본 체크아웃 | 호출 세션이 병합을 끝내거나 거둔 뒤 `grant_check.sh` 를 다시 부릅니다 |
| `메인 체크아웃에 미커밋 변경: …` | 기본 체크아웃 | 호출 세션이 커밋하거나 치운 뒤 다시 부릅니다. 사유 끝에 `.gitignore 에 … 를 더하십시오` 가 붙었으면 그 줄을 `.gitignore` 에 더해 커밋합니다 |
| `충돌 판정 생략 — 로컬 브랜치 fr/<s> 가 없습니다` | 줄기 | 줄기가 브랜치를 지웠거나 다른 이름으로 작업했습니다. 줄기 화면을 읽어 확인하고, 원인을 모르면 허가하지 않고 사용자에게 알립니다 |
| `충돌 판정 실패 …` | 기본 체크아웃 | 브랜치 `fr/<s>` 와 기본 브랜치가 있는지 확인하고 원인을 고친 뒤 다시 부릅니다. 기본 브랜치를 정하지 못했다는 사유면 `rd-workflow/config/workflow.json` 에 `default_branch` 를 적습니다. `(git 2.38 이상 필요)` 가 붙으면 `git --version` 도 확인합니다. 원인을 모르면 허가하지 않고 사용자에게 알립니다 |
| `작업 상태가 '아카이브 보류' 가 아님: …` | 줄기 | 줄기에 보냅니다(아래) |
| `worktree 없음: …` | 줄기 | 허가하지 않고 사용자에게 알립니다 |
| `자동 해소 대상이 아닌 충돌: <파일들>` | 줄기 | 줄기에 보냅니다(아래) |

- 줄기 쪽 사유는 `herdr agent prompt <에이전트 이름>` 으로 사유와 함께 보냅니다: 「`bash rd-workflow/scripts/rd publish cancel` 로 요청을 거두고, 충돌 파일을 기본 브랜치의 내용에 맞춰 fr 브랜치에서 고친 뒤(보호 트리가 바뀌면 재seal) 다시 요청하십시오」.
- **줄기 브랜치에 기본 브랜치를 병합하게 하지 않습니다.** seal 의 보호 트리 해시가 깨집니다.
- 다시 요청이 오면 처음부터 점검합니다.
- 사용자에게 HOLD 사유와 처리 내용을 한두 줄로 보입니다.

#### 호출 세션의 압축

계정 자동 압축을 끈 사용자를 위한 절차입니다. 자동 압축이 켜져 있어도 해가 없습니다. 호출 세션은 잃을 게 없는 시점에 스스로 압축합니다.

- 부르는 시점: `log.md`·`active.tsv`·보고 파일에 상태를 남긴 턴을 끝내기 직전입니다. 보통 줄기 마감을 끝낸 턴, 감시 이벤트에 「할 일 없음」 으로 답한 턴입니다.
- 부르지 않는 시점: 발행 허가나 마감 절차의 중간, 기본 체크아웃에 호출 세션의 미커밋 변경이 있을 때입니다.
- 방법: `bash rd-workflow/scripts/fr_do/self_compact.sh 80 600 <회차>` 를 `run_in_background` 로 겁니다. `<회차>` 는 이 호출 세션이 맡은 회차 값(착수 줄의 `회차`)입니다. 스크립트는 이 세션이 `idle`·`done` 이고, 입력줄이 비었다고 확인되고, 컨텍스트가 80% 이상일 때만 `/compact` 를 입력합니다. 사람이 입력창에 치는 중이면 보내지 않고 기다립니다(최대 600초). 마지막 줄은 `SENT <N>%` 또는 `SKIP <사유>` 이고 줄 끝에 ` 회차=<회차>` 가 붙습니다. rc 는 항상 0 입니다.
- 결과 처리: 백그라운드 완료 알림이 오면 마지막 줄로 아래 표의 행동을 합니다. 회차는 줄 끝의 `회차=` 값을 씁니다(알림이 압축 뒤나 다른 회차 착수 뒤에 와도 건 회차에 연결됩니다). 압축이 필요했을 수 있는데 건너뛰었으면 사용자가 알아야 하기 때문입니다. 이 결과를 처리한 턴에서는 `self_compact.sh` 를 다시 걸지 않습니다(다시 걸면 같은 사유의 `SKIP` 이 대기 상한마다 이어집니다).

| 마지막 줄 | 종류 | 호출 세션 행동 |
| --- | --- | --- |
| `SENT <N>%` | 압축함 | 알리지 않습니다 |
| `SKIP 컨텍스트 N% < 80%` | 필요 없음 | 알리지 않습니다 |
| `SKIP herdr pane 아님…`, `SKIP 대기 상한 … — 상태줄의 컨텍스트 표시를 읽지 못함 …` | 고정 사유. 설정을 바꾸기 전까지 부를 때마다 같습니다 | `log.md` 에서 `압축 건너뜀 회차=<줄 끝의 회차> <사유>` 줄을 찾습니다. 없으면 사용자에게 한 줄로 알리고 그 줄(`압축 건너뜀 회차=<회차> <사유> <시각>`)을 덧붙입니다. `<사유>` 는 `herdr pane 아님` 또는 `상태줄 판독 불가` 입니다. 있으면 알리지 않습니다 |
| `SKIP 대기 상한 … — 승인·선택 창이 떠 있음`·`세션이 계속 작업 중`·`세션 상태를 확인하지 못함`·`입력창에 글이 남아 있음`·`상태줄·입력줄이 화면에서 가려짐 …`, `SKIP /compact 입력 실패…` | 일시 사유. 다음 회에는 압축될 수 있습니다 | 매번 사용자에게 한 줄로 알립니다. `log.md` 에는 남기지 않습니다 |

- 알림 문구: 「자기 압축을 건너뛰었습니다 — <SKIP 뒤 사유 문장>. 필요하면 이 탭에서 `/compact` 를 직접 입력하십시오」. 고정 사유면 뒤에 붙입니다. 상태줄 판독 불가: 「상태줄에 `NN% NNNk/` 형식의 컨텍스트 표시가 보여야 동작합니다. 이 회차에는 다시 알리지 않습니다」. herdr pane 아님: 「herdr 안에서 띄운 세션에서만 동작합니다. 이 회차에는 다시 알리지 않습니다」.
- 압축 뒤 이어 가기: 감시(Monitor)는 압축과 상관없이 돕니다. 다음 감시 이벤트가 오면 `log.md` 와 `active.tsv` 로 상태를 다시 잡습니다.

### 3. 마감과 재선정 (`REPORT …/<s>-closing.md` 가 오면)

1. 보고 파일을 끝까지 읽습니다.
2. 정리합니다.

   ```bash
   bash rd-workflow/scripts/fr_do/close.sh <s>
   ```

   - 1절 2단계의 `stale` 정리에서 이 절로 왔으면 이 단계의 모든 `close.sh` 호출(아래 재시도 포함)에 `--stale` 을 붙입니다(`close.sh <s> --stale`). `--stale` 은 탭을 닫지 않습니다. 에이전트 이름으로 찾은 탭이 같은 이름을 쓰는 다른 줄기의 것일 수 있기 때문입니다.

   - 마지막 줄이 `CLOSED <s>` 면 정리가 끝났습니다. `active.tsv` 에서 그 줄이 빠지고, `reports/` 의 그 줄기 보고 파일은 `waves/closed/` 로 옮겨집니다(`보고 보관: <경로>` 줄).
   - 마지막 줄이 `NOT-CLOSED <s> (worktree 또는 로컬 브랜치 fr/<s> 가 남음)` 이면 함께 나온 `rd task list` 줄(예: 「정리 보류 — 점유」)이 정리 보류 사유입니다. 사유를 없앤 뒤 `close.sh <s>` 를 다시 부릅니다.
   - 마지막 줄이 `NOT-CLOSED <s> (git pull --ff-only 실패)` 면 기본 체크아웃 갱신이 실패한 것입니다. `git status` 로 원인(미커밋 변경, 갈라진 이력)을 확인해 없앤 뒤 다시 부릅니다.
   - 사유를 없앨 수 없으면 사용자에게 사유와 남은 worktree 경로·브랜치 `fr/<s>` 를 알립니다. `active.tsv` 의 줄은 남아 있으므로 로컬 브랜치 `fr/<s>` 가 있는 동안 그 줄기의 소유 파일은 재선정에서 계속 보류됩니다.
3. 보고의 「호출 세션」 담당 행동을 처리합니다. 흔한 것은 테스트 등록과 문서 한 줄 보완입니다. 테스트 등록·검증은 프로젝트 규칙의 검증·테스트 등록 절차를 따릅니다. 등급은 프로젝트 규칙의 등급 판정을 따르고, 고친 영역의 검증을 돌려 통과를 확인합니다.
4. FR 후보: 재현·관측 근거가 있는 것만 등록합니다. 관측 1회나 추정은 「목록만」 으로 남기고 이유를 적습니다. 마감 보고의 「REQUEST review 분할 후속」 절에 있는 후속 FR 은 리뷰에서 범위를 정했으므로 이 근거 기준 없이 등록하고, 보고의 AC·제약·선행 FR 을 상세에 옮깁니다. 등록은 `/fr add` 절차(items + 인덱스 행 → `rd task fr-register` → `fr_relations.sh validate`)입니다.
5. 줄기의 발행(`archive.sh`)이 연결된 Issue 를 닫습니다. 발행 출력이나 마감 보고에 `WARNING — Issue 닫기 실패` 가 있으면 그 재실행 명령을 실행합니다. 재실행이 실패해도 마감은 유지하고 출력을 보고에 적습니다.
6. `log.md` 에 마감 줄(merge 커밋, 처리한 후속, 등록·보류한 FR 후보)을 덧붙입니다.
7. 사용자에게 보고합니다.
   - 줄기 결과: FR 별 완료·보류.
   - 처리한 후속과 등록한 FR 후보(「목록만」 포함).
   - 남은 줄기: `active.tsv` 의 slug 목록.
   - 커밋·issue·저장소는 `https://` 로 시작하는 전체 URL 로 씁니다.
8. 재선정: 사용자가 「더 띄워」 처럼 계속을 지시했거나 처음 지시가 착수 가능한 FR 전부였으면 「1. 고르기」 부터 다시 합니다. 설계 문답(1절 6단계)은 다시 묻지 않고, 설계 문답 값과 회차 값(`--model`·`--effort`)은 마감한 줄기의 회차 착수 줄 값을 이어 씁니다(찾는 방법은 2절 띄우기 5단계). 새 줄기의 모델·effort 는 1절 7단계로 다시 정합니다. `pick.py` 는 `active.tsv` 를 읽어 실행 중 줄기가 맡은 FR, 실행 중 줄기와 겹치는 FR, 동시 상한을 넘는 FR 을 `hold` 로 냅니다. 실행 중 줄기는 로컬 브랜치 `fr/<slug>` 가 있는 줄기입니다. 재선정의 `pick.py` 에는 이 회차의 `중복 착수 제외` 줄 stem 을 `--exclude` 로 넘깁니다(1절 1단계). 새로 띄울 줄기가 없으면 착수 보고 없이 「새로 띄울 줄기 없음」 한 줄만 보입니다.
9. `active.tsv` 가 비고 재선정할 줄기도 없으면 감시를 멈추고 「모든 줄기 마감」 과 전체 요약을 보입니다.

### 4. 무인 (`--headless`)

1. 후보를 고릅니다: `python3 -I rd-workflow/scripts/fr_do/pick.py --mode headless [--slugs "<s> <s>"]`. 출력은 `order`(우선순위 순 실행 후보)와 `skip` 입니다. 무인은 `idea` 상태를 고르지 않습니다.
2. 선별합니다. `order` 의 FR 마다 아래를 봅니다.
   - `revisit when` 미도래와 해결 흔적은 「1. 고르기」 3단계와 같습니다.
   - autopilot 적합성: `rd-workflow/claude_skills/autopilot/SKILL.md` 의 「autopilot 적합성 기준」 으로 가능 / 조건부 가능 / 불가를 판정합니다(`/fr inspect` 와 같은 기준). 가능만 통과합니다. 조건부 가능은 충족 조건이 이미 채워졌을 때만 통과합니다.
3. 착수 보고를 보입니다. 첫 줄은 발행 정책입니다.

   | `--finish` | 첫 줄 |
   | --- | --- |
   | `push` 또는 생략 | `발행: push(원격까지)` |
   | `merge` | `발행: merge(로컬 병합까지)` |
   | `none` | `발행: none(fr 브랜치 커밋까지)` |

   둘째 줄은 `bash rd-workflow/scripts/model_select.sh headless <받은 --model·--effort 플래그>` 의 출력입니다. 플래그가 없으면 인자 없이 부릅니다. exit 1 이면 엔진을 부르지 않습니다. stderr 전체를 그대로 보이고 멈춥니다. 값 형식·설정 파일·CLI 지원 문제는 `⚠️` 이유 줄로, 값 없는 플래그·중복 플래그는 `사용법:` 줄로 나옵니다.

   그 아래 실행할 FR 목록(순서대로)과 「뺀 FR」 표(`skip` 줄과 선별에서 뺀 FR, 이유)를 둡니다. 사유가 `상태 idea` 인 FR 은 이유 칸을 「상태 idea — groom 대상 (`/fr groom <slug>`)」 으로 적습니다. 무인은 사람이 답해야 하는 groom 을 돌리지 않고 표시만 합니다.
4. 통과한 FR 이 0건이면 엔진을 부르지 않습니다. 「실행 대상 없음」 과 FR 별 제외 사유를 보이고 끝냅니다.
5. 회차 로그를 먼저 만들고, 그다음 엔진을 `run_in_background` 로 실행합니다. 두 단계는 서로 다른 Bash 호출입니다. 셸 변수는 다음 Bash 호출로 넘어가지 않으므로, 첫 호출이 출력한 절대 경로를 이후 모든 호출에 문자 그대로 씁니다.

   첫 호출(일반 실행)은 로그를 만들고 그 절대 경로를 출력합니다.

   ```bash
   mkdir -p rd-workflow-workspace/.lifecycle/fr-do
   mktemp "$PWD/rd-workflow-workspace/.lifecycle/fr-do/headless-<YYYYMMDD-HHMMSS>.XXXXXX"
   ```

   둘째 호출(`run_in_background`)은 엔진을 그 로그에 붙여 씁니다.

   ```bash
   RD_RALPH_SLUGS="<통과한 short-title들>" RD_FINISH_POLICY=<push|merge|none> \
     bash rd-workflow/scripts/ralph_drain.sh [--model <값>] [--effort <값>] >> "<첫 호출이 출력한 절대 경로>" 2>&1
   ```

   - `mktemp` 는 끝의 `X` 만 바꾸므로 확장자를 붙이지 않습니다. 같은 초에 시작한 두 회차도 로그를 나눠 씁니다.
   - 엔진 출력은 `>>` 로 씁니다. 받은 `--model`·`--effort` 플래그만 엔진 명령 끝에 그대로 붙입니다.
   - 첫 호출이 출력한 절대 경로를 아래 확인과 6단계 요약에 그대로 씁니다.
   - `--finish` 를 생략했으면 `RD_FINISH_POLICY=push` 를 명시해 넘깁니다. 엔진을 직접 실행할 때의 기본값은 `merge` 입니다.
   - 엔진은 매 반복 지정 목록 안에서 다음 FR 을 골라 `autopilot_headless.sh` 로 완주합니다. 완료·blocked 된 FR 은 다음 반복에서 빠집니다.
   - 엔진을 띄운 뒤 시작 안내 전에, 그 회차 로그에서 `ralph_drain: 무인 세션 모델:` 줄 또는 엔진 종료를 기다립니다(1초 간격, 최대 30초). 비교할 때는 그 줄 앞의 `ralph_drain: ` 접두를 떼고, 나머지를 착수 보고의 둘째 줄과 견줍니다. 결과는 네 갈래입니다.

   | 결과 | 보이는 것 |
   | --- | --- |
   | 줄이 나오고 접두를 뗀 나머지가 착수 보고의 둘째 줄과 같음 | 「무인 실행을 시작했습니다 — 대상 N건, 로그: <절대 경로>」 |
   | 줄이 나오고 다름 | 「실제 적용 값으로 정정: <접두를 뗀 줄>」 과 위 시작 안내 |
   | 줄 없이 엔진이 끝남 | 시작 안내를 보이지 않습니다. 로그의 `⚠️` 줄 전부와 마지막 `ralph_drain:` 줄을 그대로 보이고 「무인 실행을 시작하지 못했습니다 — 로그: <절대 경로>」 로 끝냅니다 |
   | 30초 안에 둘 다 없음 | 시작 안내 대신 「설정 확인 대기 중 — 로그: <절대 경로>」 |

6. 끝나면 로그의 `---- ralph_drain 요약 ----` 절을 사용자에게 옮깁니다: 완료 건수, blocked 건수와 사유, 종료 사유, 무인 세션 모델, 대기 상세, 실행 비용 합계, 정리 잔여.
   - 5단계에서 「설정 확인 대기 중」 으로 끝났다면 엔진 종료 알림이 온 뒤 로그를 같은 순서로 다시 봅니다. 줄이 없으면 위 「줄 없이 엔진이 끝남」 안내로 마무리합니다. 줄이 있으면 그 줄을 요약 앞에 붙입니다.

   | 엔진 종료 | 뜻 |
   | --- | --- |
   | exit 0 `queue-empty (지정 목록 소진)` | 지정 FR 을 모두 처리함 |
   | exit 0 `queue-blocked (의존 대기 — 지정 목록에 착수 가능 FR 없음)` | 남은 FR 이 선행 FR 을 기다림. 대기 상세를 보임 |
   | exit 1 | 중단(관계 판정 불가, 반복 상한, harness 오류 재발 등). 종료 사유와 로그 경로를 보임 |

   blocked FR 은 `/fr status <slug> validated` 로 되돌려 다시 시도할 수 있다고 알립니다.

7. 사용자가 무인 실행에서 회차별 subagent 모델·effort 를 물으면 transcript 에서 찾습니다. Status 가 `구현 중` 일 때 Agent 호출마다 hook(`subagent_dispatch_display.sh`)이 넘긴 값과 설정·출처·경고를 한 줄로 남깁니다. 무인 실행은 session_id 를 남기지 않으므로 작업 이름과 실행 시각으로 찾습니다. 무인 실행을 시작한 폴더(작업 worktree 가 아니라 명령을 실행한 기본 체크아웃)에서 아래 명령을 실행합니다. `<작업 이름>` 은 FR slug 입니다. jq 가 필요합니다.

   ```bash
   d="${CLAUDE_CONFIG_DIR:-$HOME/.claude}/projects/$(pwd | sed "s/[^A-Za-z0-9]/-/g")"
   k="subagent 넘긴 값 (<작업 이름>)"
   command ls -tr "$d" | while IFS= read -r n; do
     case "$n" in *.jsonl) ;; *) continue ;; esac
     out="$(jq -r --arg k "$k" 'select(.attachment.type == "hook_system_message" and ((.attachment.content // "") | contains($k))) | .timestamp + "  " + .attachment.content' "$d/$n")"
     [ -n "$out" ] && printf "== %s\n%s\n" "$d/$n" "$out"
   done
   ```

   `ls -tr` 는 파일 이름만 내므로 설정 폴더 경로에 공백이 있어도 쪼개지지 않습니다. `command` 는 `ls` 를 다른 도구(`eza` 등)로 바꾼 셸 별칭을 건너뜁니다. 파일 제목은 그 파일에 이 hook 의 `hook_system_message` 항목이 있을 때만 냅니다. 대화에서 같은 문자열을 인용한 transcript 는 나오지 않습니다. 그 작업의 transcript 를 오래된 것부터 나열하고, 회차마다 호출별 표시 줄과 기록 시각(UTC)을 냅니다. 같은 FR 을 재개해 여러 회차가 나오면 실행한 시각으로 고릅니다.

### 5. `/fr batch` 별칭

`/fr batch` 는 `/fr do --headless` 의 별칭입니다. 이번 배포까지 동작하고 다음 배포에서 없어집니다.

1. `bash rd-workflow/scripts/fr_do/batch_legacy.sh` 를 실행하고 출력을 그대로 사용자에게 보입니다.
   - 첫 줄은 항상 이관 안내입니다. 둘째 줄은 발행 기본값 안내(`push`, `--finish merge` 로 바꿈)입니다.
   - 남은 batch manifest(`rd-workflow-workspace/.batch-manifest.json`)가 있으면 이어 처리할 slug 목록이 나옵니다. 읽지 못하면 그 경로를 직접 열어 보라는 안내가 나옵니다.
   - rc 는 항상 0 입니다.
2. 인자를 그대로 `/fr do --headless <인자>` 로 처리합니다(「4. 무인」 절).
3. 남은 manifest 파일은 지우지 않습니다. 사용자가 확인한 뒤 지웁니다.

### 하지 않는 것

- 줄기의 다이얼로그(`blocked`)에 입력을 보내지 않습니다. 승인은 사람이 합니다.
- 되돌리기 어려운 선택과 설계 문답 질문을 줄기 대신 답하지 않습니다(「위임 답변 경계」).
- 줄기 브랜치에 기본 브랜치를 병합하게 하지 않습니다.
- 패턴으로 프로세스를 죽이지 않습니다(`pkill -f` 금지). 멈출 때는 task ID·PID 로 합니다.
- 호출 세션이 만들지 않은 탭·pane 을 닫지 않습니다. `close.sh` 는 promote 가 그 줄기용으로 띄운 slug 탭만 닫습니다.
- `/fr archive`·`park`·`status`·`push`·`take` 와 발행(`/publish`)은 사용자 요청이 있을 때만 합니다.
- 파일 삭제는 `trash` 로 합니다.
